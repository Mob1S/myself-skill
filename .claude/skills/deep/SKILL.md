# /deep — 深度二次阅读

对聊天记录进行深度二次阅读。Phase 2 蒸馏后，如果用户觉得某些记录的蒸馏不够彻底，通过 `/deep` 触发——每个发现必须有多个原文证据支撑，按维度分组展示，用户逐组确认后写入模型。

## 进入流程

### Step 0：判定工作目录

检查 `.claude/.mode_dev` 文件是否存在：
- 存在 → 基路径 = `dev/.claude/`
- 不存在 → 基路径 = `.claude/`

### Step 1：前置检查

- `{base}.claude/persona/model.md` 存在 → 继续
- 不存在 → 回复"还没有蒸馏模型，需要先完成 Phase 2。深度阅读是对已有蒸馏结果的二次分析。"

### Step 2：确定深度阅读范围

同时做两件事：

**2.1 询问用户**

```
请指定要深度阅读的内容范围：
- 指定文件路径（如 dev/mock/chat-sample.md）
- 直接粘贴对话片段
- 描述范围（如"重新分析我和 xd 的所有对话"、"深入看看情绪表达相关的记录"）

也可以说"先帮我扫描"，让我先检查哪些维度可能蒸馏不充分。
```

**2.2 主动扫描薄弱点**

如果用户说"先帮我扫描"或未指定范围，读取 `{base}.claude/persona/linguistic-fingerprint.md` 和 `{base}.claude/persona/model.md`，快速列出证据链偏弱的维度。扫描标准：

- 某维度的原文示例少于 3 条
- 人物档案中某人缺少关键记忆或互动风格描述只有一句话
- 某情绪表达只有概括描述但缺乏原文引用
- 深层行为结构缺乏具体对话场景支撑

列出后供用户选择。用户可以指定具体维度，也可以笼统地说"全部分析"。

用户范围过模糊时（如"重新看看我和朋友的聊天"但未指定文件/对话）→ 追问具体范围，同时列出可用的文件路径供选择。

### Step 3：深度分析

对用户指定的聊天记录执行深度分析。分析框架分为四层：

**第一层：语言指纹**
- 高频词：是否有新的高频口头禅未被收录？
- 句式：有没有被忽略的句式规律（如特定场景下的句式切换）？
- Emoji：特定表情是否有更细粒度的使用场景？
- 情绪表达：每种情绪是否有更丰富的表达变体？

**第二层：行为模式**
- 对话角色：主动发起/被动响应的模式是否有例外场景？
- 互动模式：是否有新的典型互动模式未被模型记录？
- 深层结构：行为背后的动机和策略是否有新线索？

**第三层：人物关系**
- 人物档案中每个人的关键记忆、互动风格是否充分？
- 称呼方式是否有遗漏或误读？
- 关系动态变化是否有线索（如亲密度上升/下降的信号）？

**第四层：底层价值观（新增）**
- 隐含信念：用户在某些话题中反复体现但未明确说出的价值观
- 一致性线索：跨场景、跨聊天对象的行为一致性
- 未被言明的需求：用户在对话中暗示但未直接表达的心理需求

**证据标准**：每个发现必须至少 3 条原文证据支撑。低于 3 条的不作为"发现"展示，但可以备注为"待验证线索"供用户参考。

### Step 4：分组展示发现

按四层维度分组展示。每组一个维度。

每个发现的格式：

```
### [维度名] 发现 N

**原文证据**：
> "原文引用 1" — 场景上下文（谁、什么情况下说的）
> "原文引用 2" — 场景上下文
> "原文引用 3" — 场景上下文

**新发现**：<一句话总结从这些证据中提炼出的模式或特征>

**与现有模型的差异**：
- ✅ 已有覆盖：<现有模型中的相关描述，如果有>
- 🆕 新增：<现有模型未覆盖的部分，如果有>
- ⚠️ 冲突：<与现有模型矛盾的地方，如果有>
```

每组展示完后询问用户：

> 这组发现里，哪些要写入模型？你可以说"全部采纳"、指定"第N条忽略"、或对某条提出修改意见。

### Step 5：用户确认后更新文件

用户逐组确认完毕后，统一更新文件。

#### 5.1 更新 model.md

增量更新，版本号 +0.1：

- **数值维度**（高频词排名等）：新证据纳入重新排序
- **定性维度**（情绪表达、互动模式等）：新条目插入对应章节；与现有条目冲突时，新证据多的一方优先，另一方降级加注"备选表述"
- **新增维度**（底层价值观）：追加新章节 `## 底层价值观`，包含价值观线索、一致性线索、未言明需求

#### 5.2 追加 linguistic-fingerprint.md

在文件底部追加，保留原始分析不覆盖：

```
## 深度分析补充 V{new_version} ({date})

### 新增/修正高频词
...

### 补充情绪表达
...

### 补充特殊语言习惯
...

### 补充互动模式
...
```

#### 5.3 更新 person-profiles.md

如果新发现涉及特定人物（关键记忆、互动风格细节），合并到对应人物条目。新人物则追加。

#### 5.4 追加 CHANGELOG.md

```markdown
## [V{new}] - {date}
- /deep 深度阅读：{范围描述}
- 采纳 N 条新发现
  - 语言指纹：N 条
  - 行为模式：N 条
  - 人物关系：N 条
  - 底层价值观：N 条
```

### Step 6：输出完成信息

```
/deep 完成。

本次深度阅读：
- 分析范围：{范围描述}
- 发现总数：N 条
- 采纳：N 条
- 忽略：N 条

模型已更新至 V{new_version}。
```

## 边界处理

| 场景 | 处理 |
|---|---|
| 无模型可读 | 提示需先完成 Phase 2 |
| 用户指定的范围太模糊 | 追问具体范围，列出可用文件路径供选择 |
| 深度阅读后无新发现 | 诚实告知"这次深度阅读没有发现与现有模型显著不同的模式，现有蒸馏已经覆盖得比较全面"，不强行编造 |
| 用户在 /test 中调用 | 不受锁定，正常执行。完成后提醒"测试仍在进行中" |
| 用户在 /train 中调用 | 不受锁定，正常执行。完成后提醒"训练仍在进行中" |
| 用户中断 | 用户说"不用了""就这些吧"时，保存已确认的发现，丢弃未确认的部分 |
| 对话原文量大 | 分批次分析——每批展示发现、确认、更新后，再进入下一批。每批之间提示进度 |

## 模式互斥

`/deep` 不受 `/test` / `/train` 模式锁定，随时可用。

## 可重复使用

`/deep` 可多次调用。每次只更新 model.md 中受影响的章节，不重复覆盖已有内容。
