# /deep 深度阅读模块设计

## 概述

`/deep` 是一个独立指令模块，用于对聊天记录进行深度二次阅读。当 Phase 2 蒸馏完成后，用户发现部分聊天记录的蒸馏不够彻底时，通过 `/deep` 触发——系统深度阅读指定内容，以多原文证据链的方式输出新发现，在用户指导下更新模型和人物档案。

## 触发方式

- **独立指令**：用户输入 `/deep`，无论在任何阶段均可调用
- **Phase 2 联动**：Phase 2 Step 4 末尾新增提示："如果觉得某些聊天记录的蒸馏不够深入，可以输入 /deep 进行深度二次阅读。"

## 指令文件

`.claude/skills/deep/SKILL.md`

遵循现有 Skill 模块的轻量模式，所有逻辑内联。包含 Step 0（dev 模式判定）、进入流程、分析框架、文件更新规则、边界处理。

## 进入流程

### Step 0：判定工作目录

检查 `.claude/.mode_dev` 文件：
- 存在 → 基路径 = `dev/.claude/`
- 不存在 → 基路径 = `.claude/`

### Step 1：前置检查

- `{base}.claude/persona/model.md` 存在 → 继续
- 不存在 → 回复"还没有蒸馏模型，需要先完成 Phase 2。深度阅读是对已有蒸馏结果的二次分析。"

### Step 2：确定深度阅读范围

两步并行：

1. **询问用户**：用户可以指定文件路径、粘贴对话片段、或描述范围
2. **主动扫描薄弱点**：读取 `linguistic-fingerprint.md` 和 `model.md`，列出证据链偏弱的维度，供用户参考。例如：
   - "情绪表达-失望仅有 1 条例证"
   - "人物档案-刘佳硕缺少关键记忆"
   - "句式特征-倒装/断句模式未找到足够原文支撑"

用户可选择"按你的建议来"或手动指定范围。范围过模糊时追问具体范围。

### Step 3：深度分析

对待分析的聊天记录执行深度阅读。分析维度：

1. **语言指纹层**：高频词、句式、Emoji、情绪表达
2. **行为模式层**：对话角色、互动模式、深层结构
3. **人物关系层**：person-profiles 中的人物细节、关键记忆
4. **底层价值观层**（新增）：隐含信念、未被言明的需求、一致性线索

**证据标准**：每个发现必须有至少 3 个原文证据支撑。

### Step 4：分组展示发现

按上述维度分组展示。每个发现的格式：

```
### [维度名] 发现 N

**原文证据**：
> "原文引用 1" — 场景上下文
> "原文引用 2" — 场景上下文
> "原文引用 3" — 场景上下文

**新发现**：<一句话总结>

**与现有模型的差异**：
- ✅ 已有覆盖：<现有模型中的相关描述>（如果有）
- 🆕 新增：<现有模型未覆盖的部分>（如果有）
- ⚠️ 冲突：<与现有模型矛盾的地方>（如果有）
```

每组展示完后询问用户："这组发现里，哪些要写入模型？你可以说'全部采纳'、'第N条忽略'、或对某条提出修改。"

### Step 5：用户确认与更新

用户逐组确认后，更新文件。

## 文件更新规则

| 文件 | 操作 | 说明 |
|---|---|---|
| `model.md` | 增量更新 | 新发现合并到对应章节，版本号 +0.1 |
| `linguistic-fingerprint.md` | 追加模式 | 底部新增 `## 深度分析补充 V{new_version}` 区块，保留原始分析 |
| `person-profiles.md` | 增量更新 | 新发现的人物细节合并到对应人物条目 |
| `CHANGELOG.md` | 追加 | 记录本次深度分析的范围、采纳发现数、版本变更 |

### model.md 合并规则

- **数值维度**（如高频词排名）：新证据纳入重新排序
- **定性维度**（如情绪表达）：新条目插入；与现有冲突时，新证据多的一方优先，另一方降为"备选表述"
- **新增维度**（如底层价值观）：追加新章节 `## 底层价值观`

### linguistic-fingerprint.md 追加格式

```
## 深度分析补充 V1.2 (2026-05-21)

### 新增/修正高频词
...

### 补充情绪表达
...

### 补充特殊语言习惯
...
```

## 边界与异常处理

| 场景 | 处理 |
|---|---|
| 无模型可读 | 提示需先完成 Phase 2 |
| 用户指定的范围太模糊 | 追问具体范围，列出可用文件供选择 |
| 深度阅读后无新发现 | 诚实告知现有蒸馏已覆盖全面，不强行编造 |
| 用户在 test/train 模式中调用 | 不受模式锁定，完成后提醒"测试/训练仍在进行中" |
| 用户中断 | 保存已确认的发现，丢弃未确认部分 |
| 对话原文量大 | 分批次分析：每批展示发现、确认后进入下一批 |
